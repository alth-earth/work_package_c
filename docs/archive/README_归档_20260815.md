# 北极航线工作包 C

工作包 C 消费 B 原子提交的逐小时 `bc.risk-frame.v2` 风险窗，按船舶到达每条边的
ETA 采样风险，运行时间依赖 A*，并发布 v2 三目标路线或 v3 四层十二路线整组。

当前包版本为 `0.4.0`。详细进度、依赖和接手顺序请先读
[`work_package_c_handoff.md`](work_package_c_handoff.md)。

> [!CAUTION]
> 当前是 `demo_unvalidated` 科研工程基线，不得用于真实航行、安全或合规决策。

## 当前口径

| 项目 | 当前状态 |
|---|---|
| 工程基线 | `0.4.0`；端点映射、正式 BC ingress、v2/v3 规划、重规划与原子发布已实现 |
| B→C | 正式入口只接受完整、逐小时、canonical、原子提交的 `RiskFrame v2` 窗口 |
| C→D | 新运行可显式选择 v2 三目标或 v3 四层整组；同一运行禁止双写 |
| 验证证据 | `UV_OFFLINE=1 make check` 通过：`138 passed` |
| 未完成 | 真实主航区实源闭环、科学/真船校准和 D 消费验收 |

`formal` 表示输入的来源、身份和时间证据通过合同；它不等于风险模型或船舶参数已经
科学校准。数据 provenance 与 calibration status 必须分开报告。

## 责任边界

```text
A DatasetBundle v2 + RunContext v2
                │
                ▼
B CommittedRiskWindow / RiskFrame v2
                │  同一 execution lease
                ▼
C endpoint mapping → ETA sampling → time-dependent A*
                │
                ├─ v2 三目标兼容基线
                └─ v3 四层 × 三目标 → atomic layered latest
                                      │
                                      ▼
                                  D 只读消费
```

- A 负责数据获取、规范化、归档和回放；C 不读 A 私有数据库或缓存。
- B 提供风险、硬约束、置信度和 `environment_speed_factor`。
- C 把环境因子应用到版本化船型，并计算最终航速、ETA、成本、路线与重规划。
- C 不从 `risk_score` 或 `confidence` 重复推导物理减速，不外推风险，不把缺测当安全。

## 快速开始：只用于工程冒烟

```bash
cd /root/my_project/work_package_c
make env-create
make lock
make sync
UV_OFFLINE=1 make check
make demo
```

`make demo` 使用确定性 `synthetic` 风险帧运行 **v2 三目标** smoke，输出到
`output/demo/`。它不运行正式 A→B→C，不生成 v3 四层实源验收证据。

## 正式运行入口

系统级正式运行由 [`arctic_route_orchestrator`](../arctic_route_orchestrator/) 组装 A、B 和 C；C 也提供
Python 公共入口 `RiskSourcePlanningIngress`。正式调用方必须：

1. 使用 `map_corridor_endpoints(...)` 获得有界、可审计的起终点节点；
2. 用完整 `PlanningConfiguration` 和同一 `RunContext` 创建请求；
3. 通过 committed-window execution lease 执行；
4. 对单次运行显式选择 `execute()` 或 `execute_four_layer()`。

正式 C CLI 并不存在；不得用 `synthetic-demo` 或 `legacy-plan` 代替系统编排器。
